# قائمة التحقق قبل الإطلاق (LAUNCH-CHECKLIST.md)

## إعدادات وبيانات

1. [ ] تغيير كل كلمات مرور التجربة (admin/teachers/parents/students) أو حذف حسابات seed.
2. [ ] حذف بيانات seed (`scripts/reset-demo-data.ts`) — تحقق من /admin/launch-status («حسابات تجريبية» = 0).
3. [ ] ضبط بيانات المدرسة الفعلية في `/admin/settings`: الاسم، phone، عنوان، hours، نص «عن المدرسة»، العملة وسعر الصرف.
4. [ ] مراجعة سياسة الخصوصية (`/privacy`) والشروط (`/terms`) مع إدارة المدرسة وتعديلها إن لزم.
5. [ ] إضافة رقم تواصل للدعم (في `/admin/settings` أو صفحة التواصل).
6. [ ] تحقق من `/admin/launch-status`: جميع الفحوصات التلقائية ✅.

## تقنية

7. [ ] اختبار البريد: ضبط SMTP_* و MAIL_FROM، ثم «اختبار إرسال» من `/admin/settings` (أو إرسال إشعار).
8. [ ] اختبار النسخ الاحتياطي: `sh scripts/backup.sh` ثم `sh scripts/restore.sh <file>` على نسخة تجريبية، والتحقق من البيانات.
9. [ ] التأكد من HTTPS: فتح https://الدومين وشهادة Let's Encrypt سارية.
10. [ ] اختبار الموقع على جوال حقيقي: RTL، قراءة، تسجيل دخول، نماذج.
11. [ ] التأكد من `AUTH_SECRET` قوي (≥32 بايت) وليس القيمة التجريبية.
12. [ ] التأكد من عدم وجود `.env` في حزمة التسليم.
13. [ ] مراجعة `CHANGELOG.md` و `README.md` (الإصدار v0.0.1.3).
14. [ ] التحقق من `/api/health` (200 + database ok + version v0.0.1.3).

## تشغيل

15. [ ] إعادة تشغيل الحاوية والتأكد من عمل healthcheck.
16. [ ] التأكد من النسخ الاحتياطي اليومي (logs في /backups).
17. [ ] إعداد cron/نسخة خارجية (سحب نسخة إلى جهازك شهريًا).
18. [ ] تدريب المدير والمعلمين (استخدم docs/USER-GUIDE-*.md).

## بعد الإطلاق

19. [ ] مراقبة السجلات لأسبوع (`docker compose logs`).
20. [ ] جمع ملاحظات المستخدمين وتحديث.
